# ユビキタス言語 (Ubiquitous Language)

本プロジェクト（多面待ちトレーナー）で使用されるドメイン用語の定義です。
コード内の変数名やコミットメッセージ、設計議論においてはこの用語統一に従ってください。

---

## 概念: パターン化 (Concept: Patternization)

麻雀における多面待ちは、牌の組み合わせによって無数に存在します。これらを個別に暗記・学習するのは困難です。
そこで本プロジェクトでは、**「コアとなる牌姿（形状）」を抽出・分類（パターン化）** することで、学習効率を飛躍的に高めることを目的としています。

- **正規化（平行移動）**: 平行移動して「1」から始まる形に揃えます。（例: `1112` と `2223` は同じとみなす）
- **正規化（対称形/左右反転）**: 左右反転（1⇔9, 2⇔8...）して同じ形になるものも同一パターンとして扱います。（例: `1112` と `8999` は対称形であり、正規化によって同じ `31` に統合されます）
- **型の分離**: 相乗面子によって待ちの構造が変わる場合は、異なる牌式のパターンとして扱います。

### 正規化プロセスの詳細 (Normalization Process)

牌式を一意に決定するための正規化は、2つのステップで行われます。

#### ステップ1: 平行移動（Shift）

最小の牌番号が「1」になるように全体をシフトします。

- 例: `2223`
  - 枚数配列：`[0, 3, 1]`
  - 最小牌は「2」なので、全体を `-1` シフト
  - 結果：`[3, 1]` → 牌式 `31`

- 例: `5556`
  - 枚数配列：`[0, 0, 0, 0, 3, 1]`
  - 最小牌は「5」なので、全体を `-4` シフト
  - 結果：`[3, 1]` → 牌式 `31`

#### ステップ2: 左右反転（Mirror）

左右反転（`10 - n`）した形も正規化し、**牌の並びとして**辞書順で小さい方を採用します。

##### 反転の仕組みと反転軸

麻雀の数牌（1-9）では、反転公式 `10 - n` により、**5を軸**として左右対称に変換されます。

- 反転公式: `n → 10 - n`
  - 1 ⟷ 9 (1+9=10)
  - 2 ⟷ 8 (2+8=10)
  - 3 ⟷ 7 (3+7=10)
  - 4 ⟷ 6 (4+6=10)
  - 5 ⟷ 5 (中心軸)

##### 具体例：反転軸を持つ形

実際のパターンでは、使用される牌の範囲に応じて**実効的な反転軸**が存在します。

- 例: `2223` と `5666` の関係
  - `2223`: 使用範囲 2-3、中心 2.5
  - `5666`: 使用範囲 5-6、中心 5.5
  - **反転軸**: `(2.5 + 5.5) / 2 = 4`
  - 反転の確認:
    - 2 + 6 = 8 (軸4からの距離: 2)
    - 3 + 5 = 8 (軸4からの距離: 1)
  - 両者は**軸4を中心に対称**な形

正規化の検証：

- `2223`: ソート・シフト → `(1,1,1,2)` → 牌式 `31`
- `5666`: ソート・シフト → `(1,2,2,2)` → 反転 `(10-n)` → `(4,4,4,5)` ソート→シフト `(1,1,1,2)` → 辞書順比較 → 牌式 `31`
- 結果: **両者とも同じ牌式 `31` に統合**

##### 端牌での反転例

- 例: `1112` の場合
  1. 元の形をソート・シフト：`1112` → `"1112"`
  2. 反転してソート・シフト：`(9,9,9,8)` → `(8,9,9,9)` → `(1,2,2,2)` → `"1222"`
  3. 辞書順比較：`"1112"` < `"1222"` → `1112` を採用
  4. 牌式変換：`[1,1,1,2]` → 各位置の枚数を数える → `[3,1]` → 牌式 `31`

- 例: `8999` の場合
  1. 元の形をソート・シフト：`(8,9,9,9)` → `(1,2,2,2)` → `"1222"`
  2. 反転してソート・シフト：`(2,1,1,1)` → `(1,1,1,2)` → `"1112"`
  3. 辞書順比較：`"1112"` < `"1222"` → `1112` を採用
  4. 牌式変換：`[1,1,1,2]` → `[3,1]` → 牌式 `31`
  - 反転軸: `(1.5 + 8.5) / 2 = 5` (1-9全体の中心)

このように、`1112` と `8999` は**異なる形だが、正規化により同じ牌式 `31` に統合**されます。

## 牌の表現 (Tile Representation)

### 牌式 (Haishiki)

**コア部分のみ**に着目し、その牌の枚数を順に並べた数列フォーマット。
正規化（最小牌が1になるようにシフト、および対称形の統合）を行った上で定義されます。

#### 基本的な変換ルール

牌式は、**牌の種類そのもの**ではなく、**各牌の枚数を配列として表現**します。

- 例: `1112` という形
  - 1萬：3枚、2萬：1枚
  - 枚数配列：`[3, 1]`
  - 牌式：**`31`**

- 例: `2223`
  - 2萬：3枚、3萬：1枚
  - 枚数配列：`[0, 3, 1]`（先頭の0は省略）
  - 牌式：**`031`** → 平行移動により正規化 → **`31`**

#### 採用理由 (Rationale)

旧来の「1112333型」（牌そのものを列挙）と比較して、牌式は以下の点で優れています。

- **短縮性**: 複雑な形でも短く表現できる。
  - 例: `3334555p` の場合、旧式では `1112333` (イチイチイチニサンサンサン = 7音節) と長くなるが、牌式なら **`313`** (サンイチサン = 3音節) で済む。
- **対称性の認知**: `313` のような数字の並びから、視覚的・聴覚的に対称構造（サンドイッチ形など）を認識しやすい。

#### 定義ルール

- **有効桁数**: パターンを構成する牌の範囲のみを記述します。9桁（1〜9）全てを埋める必要はありません。
- **ゼロ埋め（内部ギャップ）**: パターンの途中に牌がない場合（ギャップ）は `0` で埋めます。
  - 例: `1234` + `666` (1-4p, 6p) → 1,2,3,4,5(なし),6 なので **`111103`** となります。
- **ゼロ埋め（外部）**: パターンの外側（末尾の0）は表記しません。

- **例**:
  - `1112` (1萬が3枚、2萬が1枚) → **`31`**
  - `4555` (4萬が1枚、5萬が3枚) → シフト `1222` → 反転 `1112` → 辞書順で小さい方を採用 → **`31`**
  - `1234666` (1-4p各1枚、6p が3枚) → 内部ギャップあり → **`111103`**

## パターン・形状 (Patterns & Shapes)

### コア (Core / CorePattern)

多面待ちの要因となっている核となる牌の組み合わせ。
問題の最小単位であり、この形を認識することがトレーニングの目的です。
枚数によって「4枚形」「7枚形」「10枚形」...と分類されます。

### パターン31 (Pattern 31)

旧称: 1112型
4枚形パターンの基礎。正規化された牌式 `31` で表される形。
暗刻（3枚）＋隣接牌（1枚）の組み合わせ。

#### 正規化による形のバリエーション

- **基本形**: `1112` (牌式 `31`)
- **平行移動形**: `2223`, `3334`, ..., `8889` (牌式 `031`, `0031`, ... —正規化→ `31`)
- **対称形（左右反転）**: `8999`, `7888`, ..., `2111` (牌式 `13`, `013`, ... —反転→ `31` ※辞書順等で代表IDを決定)

#### 待ちパターンの3タイプ

Pattern 31は、端牌との位置関係や干渉によって、異なる待ちパターンを形成します。

##### 1. Normal（通常形） - 3面待ち

端を避けた位置（`2223` 〜 `7778`）に配置された形。両面（リャンメン）構造により3種類の待ちを形成します。

- 例: `2223` の場合
  - 待ち: `1萬`, `3萬`, `4萬` (3面待ち)
  - Gap構造: `(2, 1)` または `(1, 2)` のいずれか

##### 2. Penchan（辺張形） - 2面待ち

端牌（`1112` または `8999`）に配置された形。辺張（ペンチャン）により待ちが減少します。

- 例: `1112` の場合
  - 待ち: `2萬`（辺張）, `3萬`（単騎） (2面待ち)

- 例: `8999` の場合
  - 待ち: `7萬`（辺張）, `8萬`（単騎） (2面待ち)

##### 3. Interference（干渉形） - 待ち減少

干渉面子（後述）によって、待ち牌が物理的に消費される形。

- 例: `11124` の場合
  - 元の `1112` は `2萬`, `3萬` 待ち
  - `4萬` が加わることで `2-4` の嵌張（カンチャン）が形成され、`3萬` のみ待ち (1面待ち)

## 構造的関係性 (Structural Relationships)

### 干渉面子 (Interference Meld)

コアパターン以外の面子が、コアの待ち牌を**物理的に**消費してしまう現象、およびその原因となる面子。
**「パターン（牌式）は変わらないが、物理的な枚数不足で待ちが減る」** 状態を指します。

#### 具体例

- コア: `1112` (Pattern 31)
  - 理論上の待ち: `2萬`, `3萬` (2面待ち)
- 干渉面子: `24` が加わる → `11124`
  - 結果: `2-4` の嵌張が形成され、`2萬` が消費される
  - 実際の待ち: `3萬` のみ (1面待ち)
  - **牌式は `31` のまま**（構造は変わらないが、枚数制約で待ちが減少）

### 相乗面子 (Synergetic Meld)

コアパターン以外の面子が、コアと複合することで待ちの**構造そのもの**を変化・拡張させる現象、およびその原因となる面子。
**「これ（相乗面子）が組み合わさると、牌式そのものが変化し、新しい上位のパターンになる」** という関係性です。
このため、特定の牌式（例: 31）のトレーニング下において、相乗面子を含む形は生成対象外（スーパーセットとして排除）となります。

#### 具体例

- コア: `1112` (Pattern 31)
  - 理論上の待ち: `2萬`, `3萬` (2面待ち)
- 相乗面子: `333` が加わる → `1112333`
  - 結果: 新しい複合形が形成され、待ちの構造が変化
  - 実際の待ち: `1萬`, `3萬`, `4萬` など (待ちが増加・変化)
  - **牌式が `31` から `313` に変化**（構造的に異なるパターンになる）

#### 干渉面子 vs 相乗面子の違い

| 観点             | 干渉面子 (Interference) | 相乗面子 (Synergetic)        |
| ---------------- | ----------------------- | ---------------------------- |
| 影響の種類       | 物理的（枚数制約）      | 構造的（パターン変化）       |
| 牌式の変化       | **変化しない**          | **変化する**                 |
| 待ちの変化       | 減少                    | 増加・変化                   |
| トレーニング対象 | 含む（難易度調整）      | 排除（別パターンとして扱う） |

### スーパーセット (Superset)

相乗面子の結合により、あるパターンがより大きなパターンに包含されてしまう状態。

- 例: Pattern 31 (`1112`) に対して、Pattern 313 (`1112333`) はスーパーセット
- Pattern 31のトレーニング時には、Pattern 313を含む形は生成されない（別パターンとして独立して学習する）
