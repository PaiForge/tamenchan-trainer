# ユビキタス言語 (Ubiquitous Language)

本プロジェクト（多面待ちトレーナー）で使用されるドメイン用語の定義です。
コード内の変数名やコミットメッセージ、設計議論においてはこの用語統一に従ってください。

---

## 概念: パターン化 (Concept: Patternization)

麻雀における多面待ちは、牌の組み合わせによって無数に存在します。これらを個別に暗記・学習するのは困難です。
そこで本プロジェクトでは、**「コアとなる牌姿（形状）」を抽出・分類（パターン化）** することで、学習効率を飛躍的に高めることを目的としています。

- **正規化（平行移動）**: 平行移動して「1」から始まる形に揃えます。（例: `1112` と `2223` は同じとみなす）
- **正規化（対象/反転）**: 左右反転（1⇔9, 2⇔8...）して同じ形になるものも同一パターンとして扱います。（例: `1112` と `8999` は対称形であり、正規化によって同じ `31` に統合されます）
- **型の分離**: 相乗面子によって待ちの構造が変わる場合は、異なる牌式のパターンとして扱います。

## 牌の表現 (Tile Representation)

### 牌式 (Haishiki)

**コア部分のみ**に着目し、その牌の枚数を順に並べた数列フォーマット。
正規化（最小牌が1になるようにシフト、および対称形の統合）を行った上で定義されます。

#### 採用理由 (Rationale)

旧来の「1112333型」（牌そのものを列挙）と比較して、牌式は以下の点で優れています。

- **短縮性**: 複雑な形でも短く表現できる。
  - 例: `3334555p` の場合、旧式では `1112333` (イチイチイチニサンサンサン) と長くなるが、牌式なら **`313`** (サンイチサン) で済む。
- **対称性の認知**: `313` のような数字の並びから、視覚的・聴覚的に対称構造（サンドイッチ形など）を認識しやすい。

#### 定義ルール

- **有効桁数**: パターンを構成する牌の範囲のみを記述します。9桁（1〜9）全てを埋める必要はありません。
- **ゼロ埋め（内部ギャップ）**: パターンの途中に牌がない場合（ギャップ）は `0` で埋めます。
  - 例: `1234` + `666` (1-4p, 6p) → 1,2,3,4,5(なし),6 なので **`111103`** となります。
- **ゼロ埋め（外部）**: パターンの外側（末尾の0）は表記しません。

- **例**:
  - `1112` (1萬が3枚、2萬が1枚) → **`31`**
  - `4555` (4萬が1枚、5萬が3枚) → 反転させて `1222` 形と見なし **`13`**

## パターン・形状 (Patterns & Shapes)

### コア (Core / CorePattern)

多面待ちの要因となっている核となる牌の組み合わせ。
問題の最小単位であり、この形を認識することがトレーニングの目的です。
枚数によって「4枚形」「7枚形」「10枚形」...と分類されます。

### パターン31 (Pattern 31)

旧称: 1112型
4枚形パターンの基礎。正規化された牌式 `31` で表される形。
暗刻（3枚）＋隣接牌（1枚）の組み合わせ。

- **基本形**: `1112` (牌式 `31`)
- **シフト形**: `2223` (牌式 `031` —正規化→ `31`)
- **対称形**: `8999` (牌式 `13` —反転→ `31` ※辞書順等で代表IDを決定)

## 構造的関係性 (Structural Relationships)

### 干渉面子 (Interference Meld)

コアパターン以外の面子が、コアの待ち牌を消費してしまう現象、およびその原因となる面子。
**「パターン（牌式）は変わらないが、物理的な枚数不足で待ちが減る」** 状態を指します。

### 相乗面子 (Synergetic Meld)

コアパターン以外の面子が、コアと複合することで待ちの構造そのものを変化・拡張させる現象、およびその原因となる面子。
**「これ（相乗面子）が組み合わさると、牌式そのものが変化し、新しい上位のパターンになる」** という関係性です。
このため、特定の牌式（例: 31）のトレーニング下において、相乗面子を含む形は生成対象外（スーパーセットとして排除）となります。

### スーパーセット (Superset)

相乗面子の結合により、あるパターンがより大きなパターンに包含されてしまう状態。
