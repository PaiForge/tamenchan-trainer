## 牌式とは

### 麻雀用語としての牌式

**牌式（Haishiki）** は、麻雀において**手牌を牌の枚数で表現した式（フォーマット）**のことです。

> 手牌を牌の枚数で表現した式（フォーマット）のこと。ある種類の牌を１１１２２３５７７７９と持っているのなら、牌式は３２１０１０３０１となる。牌式が３１１１１１１１３ならば純正九蓮宝燈聴牌ということになる。
>
> — [麻雀研究 用語集](http://www.ix3.jp/hiii/02mahken/1-01yougo.htm)

**例**: 手牌が `111p 23p 555p 7p 77p 9p` の場合

```
1萬: 3枚
2萬: 1枚
3萬: 1枚
4萬: 0枚
5萬: 3枚
6萬: 0枚
7萬: 3枚
8萬: 0枚
9萬: 1枚

牌式: "321030301"
```

### このアプリケーションでの牌式の使い方

本アプリケーションでは、牌式を**多面待ちパターンのコア部分**を識別するために使用します。

- **対象**: 13枚の手牌全体ではなく、**待ちを形成する核（コア）の部分のみ**
- **目的**: パターンを一意に識別し、学習効率を向上させる

### 基本概念

```
手牌のコア部分: 1112p
  ↓
枚数: 1番目の牌が3枚、2番目の牌が1枚
  ↓
配列: [3, 1]
  ↓
牌式: "31"  ← ❌ 旧定義（ミラー処理あり）
牌式: "13"  ← ✅ 新定義（シンプル）
```

**注**: 本アプリでは、正規化処理により**常に1から始まる相対的な位置関係**で表現します。

### 牌式の表記ルール

1. **各桁**: その位置の牌の枚数（0-4）
   - 1桁目: 1番目の牌の枚数
   - 2桁目: 2番目の牌の枚数
   - ...
2. **有効範囲**: パターンを構成する牌の範囲のみ（1から始まる）
3. **ギャップ**: 中間に牌がない場合は `0` で表現

### 例

| コア手牌 | 1の枚数 | 2の枚数 | 3の枚数 | 4の枚数 | 牌式   |
| -------- | ------- | ------- | ------- | ------- | ------ |
| 1112     | 3       | 1       | -       | -       | `31`   |
| 1222     | 1       | 3       | -       | -       | `13`   |
| 1333     | 1       | 0       | 3       | -       | `103`  |
| 1234     | 1       | 1       | 1       | 1       | `1111` |

## 正規化の目的

### 問題: 同じパターンの無数のバリエーション

麻雀の多面待ちは、平行移動によって無数のバリエーションが存在します。

```
1112p, 2223p, 3334p, ..., 8889p
```

これらを個別に扱うと学習効率が悪いため、**正規化して1つのパターンIDに統一**します。

### 正規化の要件

1. **一意性**: 同じ構造の手牌は同じ牌式に変換される
2. **可逆性**: 牌式から元の構造を復元できる（平行移動を除く）
3. **シンプル性**: 実装が複雑にならない

---

## 正規化アルゴリズム

### ステップ1: ソート

手牌を昇順にソートします。

```typescript
tiles: [2, 1, 1, 1] → [1, 1, 1, 2]
```

### ステップ2: スライド（最小値を1にする）

最小値が1になるように全体をシフトします。

```typescript
tiles: [5, 5, 5, 6]
min: 5
shift: -4 (5 - 1 = 4)

結果: [1, 1, 1, 2]
```

### ステップ3: 牌式への変換

各位置の枚数をカウントして文字列化します。

```typescript
tiles: [1, 1, 1, 2]

枚数カウント:
- 1番目の牌: 3枚
- 2番目の牌: 1枚

牌式: "31"
```

**注意**: 従来は「ミラー処理」を含めていましたが、**実装を簡略化するため削除しました**。

### ミラー処理を削除した理由

#### 旧実装（ミラー処理あり）

```typescript
// 元の形
originalSlide: [1, 1, 1, 2] → "1112" → 牌式 "31"

// ミラー形（10-n）
mirrored: [9, 9, 9, 8] → sort → [8, 9, 9, 9]
mirroredSlide: [1, 2, 2, 2] → "1222" → 牌式 "13"

// 辞書順で小さい方を選択
"1112" < "1222" ✅ → 牌式 "31"
```

#### 問題点

1. **実装が複雑**: ミラー処理のロジックが煩雑
2. **直感性の欠如**: なぜ "31" が選ばれるのか分かりにくい
3. **一般性の欠如**: 複雑なパターン（例: 3455556p）では「どちらが正規形か」の判断が恣意的

#### 新実装（ミラー処理なし）

```typescript
// 単純にスライドのみ
tiles: [1, 1, 1, 2] → 牌式 "31"
tiles: [1, 2, 2, 2] → 牌式 "13"
```

**結果**: `1112p` と `1222p` は**異なるパターンとして扱われる**

これは正しい動作です。なぜなら：

- `1112p` と `1222p` は**構造的に異なる**形
- 左右反転（ミラー）は、単なる視覚的な対称性に過ぎない
- 実際の多面待ちの学習では、個別に扱う方が自然

## 具体例

### 例1: 基本的な正規化

```
手牌: 2223p

ステップ1 (ソート): [2, 2, 2, 3]
ステップ2 (スライド): [1, 1, 1, 2]  (min=2, shift=-1)
ステップ3 (牌式): 1が3枚、2が1枚 → "31"

結果: "31"
```

### 例2: 別の開始位置

```
手牌: 5556p

ステップ1 (ソート): [5, 5, 5, 6]
ステップ2 (スライド): [1, 1, 1, 2]  (min=5, shift=-4)
ステップ3 (牌式): 1が3枚、2が1枚 → "31"

結果: "31"
```

### 例3: 逆の構造（旧実装ではミラーで統合されていた）

```
手牌: 1222p

ステップ1 (ソート): [1, 2, 2, 2]
ステップ2 (スライド): [1, 2, 2, 2]  (min=1, shift=0)
ステップ3 (牌式): 1が1枚、2が3枚 → "13"

結果: "13"
```

**旧実装との違い**: これは "31" にはならず、"13" として別パターン扱い

### 例4: ギャップを含むパターン

```
手牌: 1333p

ステップ1 (ソート): [1, 3, 3, 3]
ステップ2 (スライド): [1, 3, 3, 3]  (min=1, shift=0)
ステップ3 (牌式): 1が1枚、2が0枚、3が3枚 → "103"

結果: "103"
```

### 例5: 複雑なパターン

```
手牌: 3455556p

ステップ1 (ソート): [3, 4, 5, 5, 5, 5, 6]
ステップ2 (スライド): [1, 2, 3, 3, 3, 3, 4]  (min=3, shift=-2)
ステップ3 (牌式): 1が1枚、2が1枚、3が4枚、4が1枚 → "1141"

結果: "1141"
```

## 設計判断の記録

### なぜミラー処理を削除したのか？

#### 議論の経緯

当初、`1112p` と `8999p` を「左右対称な同一パターン」として扱うため、ミラー処理を実装していました。

```
1112p → 牌式 "31"
8999p → ミラー処理 → 牌式 "31"
```

しかし、以下の問題が指摘されました：

1. **「暗刻を先に」は31型限定の理由付け**
   - `3455556p` のような複雑なパターンでは適用不可
   - `"1141"` と `"4111"` のどちらが「特徴的」か定義不可能

2. **「昇順 vs 降順」も不正確**
   - `"1141"` の「降順版」は `"4111"` ではない
   - `"4111"` は全く別の手牌（`1111234p` など）を表現する

3. **本質: 牌の数字を小さい方から表現するだけ**
   - スライド処理により、常に1から始まる形に正規化される
   - ミラー処理は不要な複雑性を追加するだけ

#### 結論

**「牌の数字を小さい方から表現する」** というシンプルなルールに統一。

- ✅ 実装がシンプル
- ✅ 直感的に理解しやすい
- ✅ 一般的なパターンにも適用可能
- ❌ `1112p` と `8999p` が別パターンになる → **これは正しい動作**

### 今後の拡張

新しいパターンを追加する際は、以下の手順で牌式を定義します：

1. 代表的な手牌を選ぶ（例: `1112p`）
2. 正規化アルゴリズムを適用
3. 得られた牌式をパターンIDとして登録

例:

- Pattern 13: `1222p` → 牌式 "13"
- Pattern 103: `1333p` → 牌式 "103"
- Pattern 1141: `3455556p` → 牌式 "1141"
